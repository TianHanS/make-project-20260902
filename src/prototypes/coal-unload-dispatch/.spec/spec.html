卸煤调度管理主规格草案

本文档是用户与 Agent 围绕当前原型进行方案沟通、确认和持续生成的事实依据。只维护当前有效方案，并简短记录会影响当前原型的重要用户决策和变更。

当前方案

  • 原型意图：为「燃料集控平台」的「卸煤调度管理」模块交付可运行的高保真管理端原型，覆盖「卸煤点维护」「矿点卸煤排班」「LED 设定」三块能力，作为后续开发与验收的界面依据。
  • 使用场景：电厂管理员在日前/当日针对当日来煤矿点指定卸煤位置，配置结果用于推送到现场 LED 大屏引导司机卸车；本期原型聚焦管理员侧的配置与维护。
  • 当前表达：Ant Design 后台浅色风格的两个管理页面；表格、筛选、排序、日期切换、抽屉表单、二级弹窗、二次确认等核心交互可操作，数据为贴近业务的脱敏样例（前端 mock），次要交互静态展示。LED 设定通过矿点卸煤管理页内的操作按钮进入抽屉配置，不单独成页。

事实与输入

用户确认事实

  • 模块名称：卸煤调度管理，视觉方向：Ant Design 后台浅色风格。
  • 页面范围：仅「卸煤点管理」「矿点卸煤管理」两个管理页面；不做 LED 大屏页、不做平台整体外壳。
  • 数据口径：贴近业务的脱敏样例数据。
  • 交互深度：关键流程高保真可操作，次要交互静态展示。
  • LED 控制：不新增页面，在矿点卸煤管理（卸煤明细管理）页内增加「LED 设定」操作按钮；非接卸时段/接待时段默认内容仅为正文内容（无标题）；更新当日卸煤明细后自动推送卸煤要求到 LED。
  • 主规格载体：HTML。
  • 业务字段与约束（PRD）：卸煤点名称唯一；煤场→分区级联、变更煤场清空分区；矿点卸煤管理字段清单、筛选、排序、自动匹配、自动同步、人工新增、行编辑/行删除等，均以 PRD 原文为准。

参考资料

  • 用户提供的「卸煤调度管理」PRD（业务规约 1 卸煤点管理 / 2 矿点卸煤管理）。

当前假设

  • 「关联分区」隶属煤场，随煤场联动；变更煤场时清空分区。
  • 「LED显示矿点名」为矿点在 LED 大屏的展示名，默认取矿点简称，简称为空时取矿点全名。
  • 「自动匹配」的历史最近匹配用前端 mock 规则模拟：按同名矿点的历史卸煤点记录匹配，取最近一次。
  • 创建人「自动同步」以固定样例账号「系统」占位；人工操作的操作人取样例「王工（admin）」。
  • 鉴权、登录、权限、真实接口、导出、多厂区切换均不在本期。
  • LED 非接卸/接待时段默认正文以示例文案预填、可直接编辑；接卸时段内容由当日卸煤明细动态生成，不在 LED 设定中配置。

原型范围

本次呈现

  • 卸煤点管理页：列表 + 新增/编辑抽屉 + 删除二次确认。
  • 矿点卸煤管理页：按卸煤点分组的列表 + 筛选 + 排序 + 来煤日期切换（前一日/后一日/选日期）+ 自动匹配流程 + 人工新增（嵌套抽屉选矿点/卸煤点）+ 行编辑 + 行删除 + 列显隐定制。
  • LED 设定（矿点卸煤管理页内按钮入口）：抽屉配置非接卸时段、接待时段的默认正文内容并保存；更新当日卸煤明细后自动推送卸煤要求到 LED（模拟提示）。

本次不呈现

  • LED 大屏司机引导屏页面（作为场景说明保留，不单独成页）。
  • 平台外壳与其他模块菜单（独立模块呈现）。
  • 真实后端、鉴权/权限、服务端分页/导出、多组织/多厂区切换。

设计基底与用户决策

设计基底与原型特有调整

  • 采用设计基底：Ant Design 后台浅色（用户指定，本地无现成 antd 主题文件），用原型目录内 CSS tokens 还原 antd 视觉，不引入 antd 运行时依赖。
  • 关键 tokens：主色 #1677ff / hover #4096ff、布局背景 #f0f2f5、卡片 #ffffff、边框 #f0f0f0、正文 rgba(0,0,0,.88)、次要文字 rgba(0,0,0,.65)、表头 #fafafa、基准字号 14px、控件圆角 6px。
  • 继承方式：严格遵循 Ant Design 后台浅色规范；控件形态对齐 antd（Button / Table / Drawer / Modal / Form / Select / DatePicker / Message / Popconfirm）。
  • 本原型特有调整：无（沿用 antd 默认配色与交互习惯）。

当前待确认事项

  • 无关键待确认（LED 大屏补充页作为后续可选阶段，不影响本期）。
